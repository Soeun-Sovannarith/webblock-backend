# Security rules (always apply)

## Secrets
- Never read, print, copy or write `.env*`, private keys, tokens, `application-prod*`, or anything under `secrets/`.
- Never hard-code credentials, API keys, client secrets or connection strings. Read them from config-server or environment variables. Placeholders in docs look like `<client-secret>`.
- Never put secrets, tokens, OTPs, passwords or full card data in logs, exceptions, test fixtures, commit messages or docs.
- If you find a secret already committed, stop, do not copy it anywhere, and tell the user so it can be rotated.

## Data and input
- Treat every external input as untrusted: HTTP bodies, query/path params, headers, RabbitMQ messages, LLM output, file names.
- Validate at the boundary (Bean Validation in Spring, Pydantic in Python). Reject invalid input; do not "fix it up".
- Parameterized queries only. No string-built SQL, shell commands or file paths from user input.
- Never bind request bodies straight onto entities (mass assignment); map through DTOs.
- Personal data (email, phone, name) is PII: log an id, never the value. Mask it in error messages.

## Access
- Authentication is Keycloak (OIDC/JWT). Never roll your own token, password hashing or session scheme.
- Authorize on every request at the service, not only at the gateway: check role AND ownership of the resource.
- Take the caller's identity from the JWT, never from a request field or header the client controls.
- Least privilege: service accounts, DB users and RabbitMQ users get only the rights they need.

## Dependencies and execution
- Do not add or upgrade a dependency unless the task requires it; say why and which version.
- Never run code generated by an LLM or received from a user. Never `eval`/`exec` untrusted input.
- Do not disable TLS verification, CSRF protection or security filters to make something work.

## When unsure
Stop and ask. A paused task is cheaper than a leaked secret.

Example: a controller takes `ownerId` from the JSON body. Read it from the JWT `sub` instead, and load the resource with `findByIdAndOwnerId(...)`.
