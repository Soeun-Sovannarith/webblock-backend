# security-reviewer memory

Verified baseline of controls (2026-10-28, updated 2026-10-31 against branch `fix/prepare-for-integration`). Re-verify any that a diff touches, and update the line if it moves.

- GLM path validation: `app/services/glm.py` `_allowed_path`/`validate_changes`. It rejects null bytes and drive letters, normalises with posixpath, rejects a leading `/` and `..`, enforces `ALLOWED_PATH`, and rejects `HARNESS_OWNED`, `HARNESS_MODULES` (extension siblings, so `lib/db.tsx` can't shadow `lib/db.ts`), `HARNESS_OWNED_DIRS`, `RESERVED_PATHS` and duplicates, plus `PROTECTED_FROM_DELETE` for deletes. All four code entry points go through `_code_request`.
- Workspace boundary: `app/services/build_runner.py` `write_workspace` (`resolve()` + `is_relative_to`).
- Docker sandbox: `_run_docker_sdk` and `_docker_cmd` both set cap_drop ALL, no-new-privileges, `BUILD_MEMORY`/`BUILD_CPUS`, pids 512 and the host uid:gid. `INSTALL` uses `bridge` with `--ignore-scripts`; `BUILD` uses `none`.
- SQL: `store.py` f-strings interpolate only `PROJECT_COLUMNS`/`PAGE_COLUMNS`, `FOR UPDATE`, and `sets` built from keys of code/Pydantic-controlled dicts. Values are always bound params.
- Onboarding: `schemas/business.py` `sanitize_text`; `drizzle_generator` was deleted (db/schema.ts is now a fixed template), so the old `_escape_ts`/`*/` header weakness is gone.
- Site catalog (sql/007_catalog.sql, verified 2026-10-31): per-site role `site_<hex>` in group `webblock_site`, RLS via `catalog.current_website_id()` (caller rights, search_path pinned, all relations qualified). Policies/defaults store OIDs, so site search_path can't shadow them. `track_storage` SECURITY DEFINER only touches NEW/OLD.website_id rows. No cross-site path found.
- Recurring weakness (2026-10-31): harness runs `db/seed.sql` (`site_catalog.prepare_site`) as the RLS-bypassing owner with the default `"$user", public` search_path, and the seed has `varchar = text` (`c.slug = v.category_slug`). If untrusted roles can CREATE in public (PG<=14 or pg_upgraded DB), a `public.=(varchar,text)` trojan runs as the harness. Check public CREATE on every target DB.
- Seed SQL: `seed_generator.literal()` quote-doubling is sound only while the server's `standard_conforming_strings` is on; the `SET LOCAL ... = on` inside the same simple-query string does not affect lexing of that string. No user text in comments any more; seed is re-rendered from data every run (`scaffold.render_seed_sql`).
- Recurring weakness (2026-10-31): `deployment.deploy` puts `resp.text[:500]` in `DeploymentError`, which lands in run log, CHECK_REPORT, error_message and `releases.failure_summary`; the request body carries `site_env` secrets (PGPASSWORD, STORAGE_SECRET_ACCESS_KEY, KEYCLOAK_CLIENT_SECRET), so an echoing receiver leaks them.
- Site media (`app/templates/site/lib/media.ts`): nosniff + `CSP: default-src 'none'; sandbox`, non-image types as attachment. MIME is the client's `file.type` (`portal/lib/files.ts`), no magic-byte check. `lib/db.ts` maps PGSSLMODE `prefer` to no TLS.
- Generated-site portal auth: Keycloak OIDC in `app/templates/site/lib/portal-auth.ts` (sealed AES-GCM cookie, back-channel revocation in `catalog.portal_revoked_sessions`, fail-closed). `ownerSql`/`isSignedIn` gating protects template code only; GLM code can call `getSql()` directly (RLS still limits it to its own site).
- Secrets: `.env` is denied to Claude (settings + hooks). GLM errors include `resp.text[:500]` (the response body, not the request), so check any change that would add request headers or body to errors.
